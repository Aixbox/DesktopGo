# 搜索体验优化路线图

> 用于记录 DesktopGo 主窗口搜索的后续开发事项。每次继续开发前先更新本文档中的状态、范围和验收条件。

## 当前基线

当前搜索已经完成第一阶段改造：

- 搜索范围统一为“全部 / 快捷入口 / 文件”。
- “全部”模式优先展示最多 6 个相关快捷入口，再展示文件与文件夹。
- 快捷入口支持名称精确匹配、前缀匹配、包含匹配和 Fuse 模糊匹配。
- 上下键可以跨快捷入口和文件结果连续导航，回车启动当前选中项。
- 文件搜索继续使用 Everything，保留筛选、排序、分页、历史和预览。
- 文件筛选在“全部”模式中明确显示为“文件 · 类型”。
- 搜索框和结果面板使用统一的定位样式，保持水平对齐。
- 相关性排序和统一键盘导航已有单元测试。

## 开发原则

- 默认保持本地优先，不加入网页、Bing 或联网搜索结果。
- 快捷入口、文件和文件夹必须在视觉上保持清晰分组。
- 结果排序应优先满足“最可能启动的内容”，而不是单纯按路径排序。
- 新增行为必须保留 Everything 的加载、分页、错误、历史和预览能力。
- 优先在 React/TypeScript 搜索层解决问题，除非确认 Everything 或 Rust/IPC 层是瓶颈。
- 每项功能完成后补充对应的纯逻辑测试或交互测试。

## 推荐实施顺序

`S-01` 当前采用 Everything 分页召回后在应用层排序，优先改善首屏和已加载页；如果后续需要跨全部结果的全局相关性排序，再单独设计候选缓存和性能边界。

`S-02` 仅记录从搜索结果成功启动的快捷入口，数据包含入口 ID、启动次数和最近启动时间，默认启用并仅保存在本机。相关性层级仍优先于使用频率；用户可在搜索设置中停用排序数据或清空全部记录。

`S-03` 切换范围时保留搜索关键词，以及仅作用于文件结果的筛选、匹配、排序和预览显示偏好；快捷入口范围不会读取这些文件查询偏好。范围变化会将快捷入口、文件和综合结果的选中项重置为新范围默认状态，并清空当前预览内容、加载态和错误态，避免旧范围的高亮或预览残留。重复点击当前范围不触发重置。

### 第二阶段：结果质量

建议先完成 `S-01`、`S-02`、`S-03` 和 `S-04`。这一阶段直接决定搜索结果是否“像一个启动器”，同时不需要改变 Rust/IPC 接口。

### 第三阶段：可理解性和效率

继续完成 `S-05`、`S-06`、`S-09`、`S-10` 和 `S-11`，重点解决用户看不懂结果、无法快速定位和筛选作用不清晰的问题。

### 第四阶段：能力扩展

在搜索结果质量稳定后，再考虑 `S-07`、`S-08`、`S-12`、`S-13`、`S-14` 和 `S-15`。

## 相关代码边界

- `src/components/Launchpad.tsx`：主窗口输入、范围切换、启动回调和搜索状态组合。
- `src/components/search/SearchPanel.tsx`：结果面板、文件虚拟列表、历史和预览布局。
- `src/components/search/ShortcutSearchResults.tsx`：快捷入口结果展示。
- `src/components/search/searchNavigation.ts`：跨结果类型的键盘导航规则。
- `src/lib/search/iconSearch.ts`：快捷入口相关性排序。
- `src/lib/search/useSearch.ts`：Everything 查询、分页、筛选、历史和选中项。
- `src/lib/search/scope.ts`：搜索范围类型和范围能力判断。

新增逻辑优先放入上述对应模块，避免继续扩大 `Launchpad.tsx` 和 `SearchPanel.tsx`。

## 每项开发的完成检查

1. 更新本文档中对应事项的状态和实现说明。
2. 为纯排序、过滤、状态转换或键盘规则增加单元测试。
3. 验证空结果、加载中、索引初始化失败、分页加载和预览切换。
4. 运行 `pnpm test`、`pnpm build`、相关文件 ESLint 和文件预算检查。
5. 检查搜索框、结果面板、快捷入口区和文件区在小窗口下没有重叠或溢出。
6. 如果涉及持久化配置或启动行为，补充升级兼容和失败回退说明。

## 明确暂不做

- 不加入网页搜索、Bing 搜索或联网推荐。
- 不为了搜索 UI 重写 Rust/IPC 搜索服务。
- 不在没有使用数据基础时宣称“常用”或“最常启动”。
- 不把系统设置和本地动作直接混入文件结果而不提供类型区分。
